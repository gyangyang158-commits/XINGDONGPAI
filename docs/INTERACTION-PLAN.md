# 交互收敛计划（先诊断，再局部修改）

## 产品与用户

星动派是赵露思生日生咖的小组共创工作台。普通成员提供想法、图片和参考；设计师将其变成可比较的方案；主办负责提名、投票截止与最终确认。本轮核心完成动作是：**把一条有署名、可追溯的想法变成预览，确认后放进灵感池**。不新增订阅、充值或用量仪表盘，当前产品没有这些业务场景。

## 已确认的问题

1. 桌面七个一级入口与四个页内工具入口重复，手机五个入口又与桌面不一致。
2. 模板、助手、上传应是同一创作台的三种开始方式，讨论不应被当作创作模式。
3. 主页面的“返回工作区”和预览的“返回上一页”重复；没有新的任务层级却制造了返回动作。
4. 模板/上传采用后跳到成功页，再点击查看，属于可用原位反馈替代的中间步骤。
5. 编辑标题/副标题会重绘整个工作区，破坏阅读与输入位置；已发布方案的小改动不应制造重复卡片。
6. 助手首屏同时展开来源、运行方式、授权、服务检查与演示预览，实际起稿动作被稀释。

## 本轮边界

沿用原生 HTML/CSS/JavaScript，不迁移框架，不改写成员原话、署名或已上传图片。不增加视觉效果、不改应援配色。保留 AI 文字发送授权、麦克风授权、主办权限、投票截止与平票裁决；这些不属于可删除的冗余。

## 改后信息架构

一级导航（桌面和手机一致）：概览 / 灵感池 / 创作台 / 评审 / 讨论。

创作台内部只保留三种方式：助手起稿 / 选模板 / 上传素材。讨论与贡献记录各有明确位置，不再到处重复出现。交付归档属于评审的后续动作；未确认最终版时显示原因和下一步，不使用无信息的跳转提示。

## 主路径

- 助手：输入或说出需求 → 生成预览 → 原位改字 → 加入灵感池。来源、工具记录和连接设置按需展开；已发布方案改字后明确“更新已发布方案”，不新增重复投稿。
- 模板：选一套 → 同页看完整预览 → 加入灵感池；成功后原位提示，可继续选择或定位已发布卡。
- 上传：选图 → 检查预览与说明 → 加入灵感池 / 提交评审；原位显示结果，不再跳成功页。
- 讨论：保留原文，当前房间内直接记录，不加入模板/上传的模式切换。

## 可执行规则与验收

- 一级导航来自同一份常量配置；桌面和手机均为五项，顺序一致；创作方式恰好三项。
- 普通主页面没有泛化返回按钮；详情页最多一个上下文明确的返回动作。
- 每个创作阶段只有一个主要提交动作；成功、空输入、无模板、无原图、AI 未连接/失败和忙碌态均说明下一步。
- 标题、副标题的改动只更新预览与按钮状态，不重新生成整页，不触发模型请求。
- 成功反馈使用同页 status 区域，重复点击不重复投稿；已发布小改动保留卡 ID、署名、点赞与评论。
- 在线 AI 和语音仍需明确授权；失败不静默伪造成成功，不自动重试付费调用。
- 字体沿用 Geist + 中文系统字，正文 14px，辅助 12px，区块标题 20px，页面标题 32px；间距以 4px 为基准，控件圆角 10px、内容面板 16px。既有大幅海报保留作品字体。
- 检查 1440px、390px 与 320px；无横向溢出，无新弹窗；既有上传、语音和动效继续可用。
